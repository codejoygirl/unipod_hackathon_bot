# Taste — Communication & Workflow
- Prefers completed work to be committed and delivered rather than left as uncommitted local changes — sometimes as a pull request (targeting the repo's default integration branch, with conventional-commit messages and a CHANGELOG entry), sometimes by simply pushing the current branch. Confidence: 0.55
- Gives terse, lowercase, under-specified instructions and relies on the agent to investigate context and infer scope; happy to answer a clarifying question when scope is genuinely ambiguous. Confidence: 0.7
- Directs frontend/UI work by handing over a reference and asking for it to be applied ("make my ui for the chatiput something like this") — sometimes a visual (e.g. a Dribbble screenshot), sometimes a pasted third-party component/integration prompt (raw source code plus its dependency and setup boilerplate, dropped in verbatim), sometimes a raw brand asset such as an icon SVG to be used verbatim ("ad here the icon for whatsapp <svg…>"). Leaves the agent to decide how much of the reference to adopt versus keep the project's existing design system, and does not expect the pasted code to be copied literally. Confidence: 0.65
- Wants LLM provider/model configuration to be env-var-driven and swappable (e.g. dropping in DeepSeek via an OpenAI-compatible base URL) rather than hardcoded, and asks for the concrete env variables needed to make a service run. Confidence: 0.5
- Wants the concrete runnable command up front ("just give me a command to ..." / "just give me commands") rather than process narration, explanations, or a walkthrough — get prerequisites in place, then hand over the copy-pasteable command with minimal prose. Confidence: 0.75
- Runs suggested commands verbatim in his own Windows PowerShell terminal, so they must be paste-safe as-is — avoid multiline here-strings and constructs that break on indentation; prefer single-line commands or constructs the agent executes itself. Confidence: 0.65
- Commands must also survive terminal line-wrapping: a very long single-line command or absolute path gets broken at the wrap points when pasted and fails (e.g. a huge `docker run` splitting mid-flag, or a long temp/scratchpad path splitting mid-string, causing `[Errno 22] Invalid argument`). Prefer short commands — e.g. picking a prebuilt image with everything needed over an inline install/build, or handing over short wrapper scripts instead of a giant one-liner — and verify them by running them herself before giving them over. Confidence: 0.6
- Wants the agent to resolve a problem autonomously — pick a sensible default and just execute it — rather than presenting a menu of options/decisions to choose from; responds to option-lists with a terse "fix that". Confidence: 0.55
- Expects the project's documented setup flow (e.g. the README's `sail up -d` / `php artisan migrate` steps) to be followed as the canonical way to run things, and will point back to it when the agent improvises a custom workaround instead. Confidence: 0.6
- Reports defects by pasting raw, verbatim output — UI state badges, error/status strings, the failed query, or browser console logs — with little or no explanation of the cause, and expects the agent to reproduce the case and root-cause it. Confidence: 0.5
- When an outcome is hard to observe, wants diagnostics instrumented directly in the app rather than inferred: asks to "console log everything" at the request boundary (full request payload, raw response and error) so a bad/blocked answer can be read without opening the network tab. Confidence: 0.4
- Expects instructions he already gave to be carried out literally and in full, including the removals: when the agent keeps something it decided was fine and only does part of the ask, he restates the original request ("just do what i told to put remove those zak-glow") instead of re-explaining — so treat any prior ask as still in force and complete it rather than partially applying it. Confidence: 0.55
- Optimizes for speed over thoroughness/optimization — pushes back on time spent tweaking or reasoning with "instead of us wasting time ... no need for wasting time," preferring to reach for a well-known off-the-shelf solution (e.g. "use open ai gpt 4") and ship rather than optimize for its own sake. Confidence: 0.6
